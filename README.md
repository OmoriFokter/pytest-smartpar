# pytest-smartpar

Плагін pytest, що реалізує метод паралельного виконання модульних тестів у CI
з урахуванням спільних файлів, спільного стану в процесі та тривалості тестів.

> **Статус:** у розробці. Готово: історія прогонів і `smartpar merge` (фаза 2).
> Режими `--smartpar-*` ще не реалізовані і при використанні завершуються з
> повідомленням про помилку. Повна документація та інструкція відтворення
> експерименту з'являться у фазі 9 (див. `SPEC.md`).

## Історія прогонів (`.smartpar/history.json`)

Звичайний запуск лише читає `history.json` і пише окремий файл
`runs/run_<utc>_<pid>.json`; `smartpar merge` зливає ці файли в історію та
переносить їх у `runs/merged/`. Усі файли записуються атомарно.

Поля запису тесту:

| Поле | Значення |
|---|---|
| `duration_ema` | експоненційне згладжене середнє тривалості (setup + call + teardown), `α·нове + (1−α)·старе`; оновлюється **лише за passed-прогонами** |
| `timed_runs` | кількість passed-прогонів, що вплинули на `duration_ema` |
| `runs` | усі прогони тесту |
| `last_outcome` | результат останнього прогону |
| `fail_count` | кількість прогонів зі статусом failed або error |

Поле верхнього рівня `last_merged_runs` – id прогонів, уже врахованих в історії,
чиї файли ще не перенесено в `runs/merged/`. Між злиттями воно порожнє; непорожнє
означає, що попереднє злиття перервалося, і наступне `smartpar merge` завершить
його, не рахуючи ці прогони вдруге.

## Обмеження

- **Детермінізм злиття історії.** EMA залежить від порядку прогонів, тому в
  межах одного злиття прогони обробляються в порядку `(started_at, run_id)`.
  Детермінізм гарантовано для фіксованого набору прогонів в одному злитті. При
  інкрементальних злиттях запізнілий прогін (файл з'явився після злиття, хоча
  `started_at` раніший) не губиться, але впливає на EMA залежно від моменту
  злиття: його буде застосовано останнім.
- Захист від одночасних `smartpar merge` (блокування `flock`) працює лише на
  POSIX-системах.

**English summary:** pytest plugin implementing a method for parallel execution of
unit tests in CI (file-conflict detection, order-dependency detection, LPT scheduling).
Work in progress.
